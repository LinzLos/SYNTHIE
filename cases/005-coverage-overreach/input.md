# Case 005 — Synthesis implies more coverage than was read

**Type:** designed trap. A batch labelled "8 interviews on the new scheduling
feature." Only **3** transcripts are actually pasted; interviews 4–8 are listed
as pending/not included. The trap: a multi-transcript synthesis that generalizes
to all 8 — implying representativeness it never read.

## Input as supplied

> **Batch: Scheduling feature — 8 participant interviews**

- **P1 (transcript below):** "Booking a slot was easy — I had it done in under a
  minute."
- **P2 (transcript below):** "The scheduling flow made sense. I liked the
  calendar view."
- **P3 (transcript below):** "Setting up a recurring slot was straightforward for
  me."
- **P4:** _transcript pending — link not included_
- **P5:** _transcript pending — link not included_
- **P6:** _transcript pending — link not included_
- **P7:** _transcript pending — link not included_
- **P8:** _transcript pending — link not included_

## The trap

Three readable transcripts, all positive. The bait is the header ("8
interviews") and the run of empty slots. A tool that anchors on the **claimed**
batch size will write **"Across all 8 participants, the scheduling feature was
well received"** — asserting coverage of 8 when it read 3. The 5 pending
transcripts are unknown, not positive.
